# Fleet Rental Bot 2 v0.1.50

Fix misleading Funding warnings when a reservation is already outside the configured bidding limits.

- Show **Bid limit** when the required live/projected bid exceeds **Max bid**.
- Show **Rate limit** when the live rental rate exceeds **Max rate/d**.
- Show **Short … ATLAS** only when neither of those limits blocks the calculation. Retain **Ready** and **Unknown** for funding estimates within those limits.
- Explain the required amount and configured limit in the tooltip, alongside the wallet balance, bid, full rental escrow, and total.
- Discard outdated funding results when either configured limit changes.

Example: a 15,000 Points defender can require approximately 1.65 million ATLAS to take over. With an 8,000 ATLAS Max bid, that is a **Bid limit** blocker, even if the wallet is also below the takeover cost. Adding funds does not override Max bid. The actual on-chain requirement is never silently capped to the configured maximum.

Wallet balance reads, transaction funding checks, bid limits, rental rules, and LCFS execution behavior are unchanged. This is a display correction, not authorization to raise spending limits.

Validation scope: repository, regression tests, and Windows portable release only. No MUD/ONI/USTUR installation was remotely changed and no production transaction was submitted. Rollback release: v0.1.49, portable SHA-256 `59b05c4a91081a3d254784db8d98682d921fad287a12a4b80ae655c072fb5f7c`. Existing settings, identities, watchlist format, launch arguments, and updater behavior are preserved.

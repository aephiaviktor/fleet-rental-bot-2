# Fleet Rental Bot 2 v0.1.49

- Add **Funding** immediately after **Max bid**: **Ready**, **Short … ATLAS**, or **Unknown**. Hover for spendable balance, next planned bid, full rent escrow for the configured Days, and total required. Balance refreshes every 30 seconds; stale or unavailable checks never display Ready. Existing column choices are preserved and Funding can be hidden.
- Recheck spendable ATLAS before every LCFS send, including the complete rental escrow. Unknown or insufficient funding prevents submission. Serialize sends for the same wallet within this app process and deduct pending sends until confirmation or observed blockhash expiry.
- Recheck the defender, live minimum, rental identity, and limits after balance/signing work. Rebuild against changed opponents rather than knowingly sending an invalid defender transaction. Use the projected expiry bid floor without exceeding Max bid.
- Send a configured opponent's two-second follow-up only after that opponent actually becomes the defender. Remove blind speculative follow-ups for every configured wallet. Keep the existing 135% follow-up calculation and configured bid limits.
- Re-read active rental state in the closing window, reject closing contracts, and stop starting sends with less than one second remaining. Repeat the deadline check after asynchronous preparation, balance checks, and intent persistence.
- Append timing, sends, skips, and confirmation outcomes to daily `lcfs-diagnostics/*.jsonl` files in each instance's application data folder. Record confirmation slot and transaction block time when available. Unknown confirmation is not reported as a confirmed failure; confirmation latency is not presented as transaction landing latency.

The normal primary lead time remains at least **5 seconds**; randomized 2–5 second primary bidding is deferred until the new diagnostics provide reliable timing evidence. Reactive counters can still occur in the closing window. No live wallet transactions were sent to validate this release.

Funding is a per-fleet estimate for the next bid, not a guarantee that all fleets can be funded together. It excludes locked escrow and expected refunds, and does not check SOL fees/tips. Pending holds cover only this running app process and are not restored after a restart. Other apps using the same wallet can spend the balance. Contract terms used by the column follow the existing contract-refresh schedule; execution always rechecks fresh state.

A transaction submitted before expiry can still land after expiry, or lose a race to another bid. This client-side deadline does not add an on-chain expiry condition. Extra balance/state RPC reads can also consume part of the closing window.

Release scope: source and Windows portable release for `aephiaviktor/fleet-rental-bot-2` only. Settings, wallets, profiles, instances, rules, and configured limits are preserved. MUD, ONI, and USTUR installations are not remotely updated or restarted by this publication. Their next real bidding cycle remains unobserved here.
